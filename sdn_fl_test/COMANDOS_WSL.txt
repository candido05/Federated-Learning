1. CRIAR AMBIENTE VIRTUAL (APENAS NA PRIMEIRA VEZ)
---------------------------------------------------

IMPORTANTE: o venv DEVE ficar no filesystem Linux (~/),
NAO no /mnt/c/ (Windows). Isso evita erros de I/O do Ray/Flower.

    # Abrir terminal WSL
    wsl

    # Criar pasta para o venv no filesystem Linux
    mkdir -p ~/sdn-fl-env
    python3 -m venv ~/sdn-fl-env/venv

    # Ativar o venv
    source ~/sdn-fl-env/venv/bin/activate

    # Atualizar pip
    pip install --upgrade pip

    # Instalar dependencias
    pip install -r /mnt/c/Users/candi/OneDrive/Desktop/Federated-Learning/sdn_fl_test/requirements.txt

----------------------------------

    cd /mnt/c/Users/candi/OneDrive/Desktop/Federated-Learning/sdn_fl_test


4. EXECUTAR COM BAGGING (todos os modelos + datasets)
-----------------------------------------------------

    bash run_bagging.sh

    Isso roda automaticamente:
    - breast_cancer x xgboost (20 rounds, 20 epocas, 3 clientes)
    - breast_cancer x lightgbm
    - breast_cancer x catboost
    - digits x xgboost
    - digits x lightgbm
    - digits x catboost

    Total: 6 experimentos sequenciais com estrategia BAGGING.


5. EXECUTAR COM CYCLING (todos os modelos + datasets)
-----------------------------------------------------

    bash run_cycling.sh

    Mesmo que acima, mas com estrategia CYCLING (1 cliente por round).
    Total: 6 experimentos sequenciais.

8. PARAMETROS DISPONIVEIS
--------------------------

    Servidor (server.py):
        --strategy      bagging ou cycling (obrigatorio)
        --dataset       breast_cancer ou digits (padrao: todos)
        --model         xgboost, lightgbm ou catboost (padrao: todos)
        --rounds        numero de rounds globais (padrao: 20)
        --num-clients   numero de clientes (padrao: 3)
        --address       IP:porta do servidor (padrao: 0.0.0.0:8080)

    Cliente (client.py):
        --client-id     ID do cliente: 0, 1 ou 2 (obrigatorio)
        --dataset       mesmo dataset do servidor (obrigatorio)
        --model         mesmo modelo do servidor (obrigatorio)
        --server        IP:porta do servidor (padrao: 127.0.0.1:8080)
        --num-clients   total de clientes (padrao: 3)
        --local-epochs  epocas locais de boosting (padrao: 20)


9. PARA USAR NO GNS3 (SDN)
----------------------------

    A unica mudanca e trocar os IPs:

    # VM Servidor (ex: 10.0.0.1)
    python server.py --strategy bagging --address 0.0.0.0:8080

    # VM Cliente 0 (ex: 10.0.0.2)
    python client.py --client-id 0 --server 10.0.0.1:8080 --dataset breast_cancer --model xgboost

    # VM Cliente 1 (ex: 10.0.0.3)
    python client.py --client-id 1 --server 10.0.0.1:8080 --dataset breast_cancer --model xgboost

    # VM Cliente 2 (ex: 10.0.0.4)
    python client.py --client-id 2 --server 10.0.0.1:8080 --dataset breast_cancer --model xgboost

    O Flower cuida de toda a comunicacao gRPC pela rede SDN.

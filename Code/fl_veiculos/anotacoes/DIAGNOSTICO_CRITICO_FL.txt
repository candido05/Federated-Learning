PADRÃO IDENTIFICADO:
--------------------
Modelo tem FORTE VIÉS para Classe 1 (majoritária):
- 25.82% da Classe 1 real é confundida com Classe 0
- 38.47% da Classe 2 real é confundida com Classe 1
- Classe 1 age como "classe padrão" quando modelo está incerto

CAUSA RAIZ:
-----------
1. THRESHOLD DE DECISÃO NÃO CALIBRADO:
   - Softmax probabilities não estão calibradas para classes desbalanceadas
   - Threshold padrão (0.5 binário, max prob multi-classe) favorece majoritária

2. FALTA DE CALIBRAÇÃO DE PROBABILIDADES:
   - Tree-based models tendem a produzir probabilidades MAL CALIBRADAS
   - Classes minoritárias têm probabilidades SUBESTIMADAS sistematicamente

3. PERDA (LOSS) NÃO PONDERA ERROS POR CLASSE:
   - softmax cross-entropy padrão trata todos erros igualmente
   - Errar na Classe 2 (6%) deveria custar MAIS que errar na Classe 1 (88%)

IMPACTO PRÁTICO:
----------------
Em aplicação real (detecção comportamento veículos):
- 43% dos casos da Classe 2 serão PERDIDOS
- Sistema será CONSERVADOR, tendendo sempre à Classe 1
- Eventos raros (Classes 0 e 2) não serão detectados confiavelmente

SOLUÇÃO PRIORITÁRIA:
--------------------
1. IMPLEMENTAR FOCAL LOSS:
   → focal_loss = -(1-p_t)^γ * log(p_t)
   → γ=2 penaliza exemplos fáceis (Classe 1)
   → Força modelo a focar em exemplos difíceis (Classes 0 e 2)

2. CALIBRAR THRESHOLDS POR CLASSE:
   → Usar Platt Scaling ou Isotonic Regression
   → Ajustar thresholds de decisão baseado em validação
   → Threshold Classe 2 deve ser MAIS BAIXO (aceitar incerteza)

3. ADICIONAR PENALIDADE ASSIMÉTRICA:
   → Custo de erro Classe 2 = 17x custo erro Classe 1 (proporcional ao desbalanceamento)
   → Implementar via sample_weights customizados

4. POST-PROCESSING:
   → Ensembling de múltiplos modelos com thresholds diferentes
   → Voting ponderado favorecendo predições de classes minoritárias

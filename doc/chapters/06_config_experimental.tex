\subsection{Ambiente Computacional}

Os experimentos foram executados em ambiente virtualizado WSL2 (\textit{Windows Subsystem for Linux 2}) sobre sistema operacional Windows 11, utilizando Python 3.12.3 e o framework de simulação do Flower \cite{flower2020} com backend Ray para orquestração dos clientes federados. Esta abordagem é recomendada para prototipagem e avaliação experimental, eliminando a necessidade de infraestrutura de rede real enquanto preserva o comportamento do protocolo federado \cite{flower2020}.

\subsection{Otimização Federada de Hiperparâmetros}

Os hiperparâmetros de cada algoritmo foram otimizados de forma federada: cada cliente executa independentemente 15 \textit{trials} de busca bayesiana via Optuna, utilizando 33\% dos seus dados locais. Os resultados são agregados no servidor via mediana --- mais robusta contra \textit{outliers} que a média aritmética --- preservando a localidade dos dados. A métrica otimizada é o TPR no ponto de operação de 5\% de FPR, com taxa de aprendizado limitada a 0,05 (\textit{safety brake}) para evitar sobreajuste no treinamento federado com \textit{warm start}. Os dados de treino foram distribuídos uniformemente entre 3 clientes, cada um recebendo aproximadamente 264.893 amostras com 2.716 instâncias de fraude (taxa de 1,03\%), preservando a distribuição de classes do dataset original. Os conjuntos de validação e teste são mantidos centralizados no servidor para avaliação global do modelo.

Ambas as estratégias utilizam \textit{warm start}: na Bagging, o melhor modelo da rodada anterior é enviado para todos os clientes; na Cíclica, o modelo é passado sequencialmente entre clientes. A estratégia Cíclica aplica adicionalmente \textit{learning rate decay} com fator 0,85 por rodada para controlar o sobreajuste do treinamento sequencial.

Cada simulação executa 15 rodadas de comunicação, e ao final de cada rodada o modelo global é avaliado no conjunto de validação utilizando dois regimes de limiar:

\begin{itemize}
    \item \textbf{Standard}: Um único limiar global calibrado para 5\% de FPR no conjunto completo.
    \item \textbf{Fair}: Limiares independentes por grupo demográfico (idade $\geq$ 50 e idade $<$ 50), cada um calibrado para 5\% de FPR no respectivo grupo. Esta técnica de \textit{post-processing} ajusta os pontos de operação separadamente para cada grupo, equalizando as taxas de falso positivo sem modificar o modelo treinado.
\end{itemize}

\subsection{Métricas de Avaliação}

As métricas reportadas para cada experimento são:

\begin{itemize}
    \item \textbf{TPR @ 5\% FPR}: Taxa de verdadeiros positivos no ponto de operação de 5\% de taxa de falsos positivos, conforme utilizado no artigo do BAF \cite{jesus2022baf} como métrica principal de desempenho em produção.
    \item \textbf{AUC-ROC}: Área sob a curva ROC, medida de discriminação independente do limiar.
    \item \textbf{FPR Ratio}: Razão entre as taxas de falso positivo dos grupos demográficos ($\min/\max$), onde 1,0 indica fairness perfeita.
    \item \textbf{Tempo de execução}: Duração total da simulação em segundos.
    \item \textbf{Bytes transferidos}: Volume total de dados transferidos entre clientes e servidor.
\end{itemize}

O tempo total do experimento completo (incluindo pré-processamento, otimização de hiperparâmetros e as 6 simulações) foi de 7.021 segundos (aproximadamente 1 hora e 57 minutos).
